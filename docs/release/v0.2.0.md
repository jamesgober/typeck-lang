# typeck-lang v0.2.0 — One Type Checker, Configured by a Profile

**The foundation.** v0.2.0 turns the scaffold into a type checker over HIR
whose behaviour is data: a type-system profile. The `dynamic` discipline
(Python, Lua, Mox) and the `static-explicit` discipline (C, Go, Zero) are
implemented completely; `gradual`, `static-inferred`, and `hm` are designed
in `dev/ROADMAP.md` and arrive in 0.5.0. Types are interned terms in a
union-find store, so shared type structure is never expanded, every traversal
is iterative, and every check runs under a budget.

## What is typeck-lang?

The semantic-analysis (SEMA) crate of the `-lang` family that checks the HIR
every LexerSketch language lowers into. Configuring one checker covers the
target languages, from Mox (dynamic) to Kraken and Iron (static), without a
type checker per language. It does not resolve names (resolve-lang) or compile
patterns (match-lang).

## What's new in 0.2.0

### Profiles as data

A `Profile` is a `Discipline` plus toggles: `subtyping`, nominal or
structural `records`, `numeric_widening`, `null_safety`, `exhaustive_match`,
`polymorphism` (traits, interfaces, typeclasses), literal defaults,
`string_add`, and `certain_errors`. Presets exist for all five disciplines.

```rust
use typeck_lang::{Profile, RecordTyping};

let p = Profile::static_explicit()
    .with_records(RecordTyping::Structural)
    .with_subtyping(true);
assert!(p.null_safety);
```

### `check` and `Checker`

`check(&hir, &profile)` is the Tier-1 call. `Checker` declares what the unit
does not define: extern values, other units' definitions, named intrinsics,
and members of host types, with types built in the result's own store.

```rust
use hir_lang::{Builder, Lit, Name, NodeRef, OpKind};
use intern_lang::Interner;
use typeck_lang::{check, Profile};

let mut names = Interner::new();
let mut b = Builder::new();
let one = b.int(1);
let yes = b.lit(Lit::Bool(true));
let sum = b.op(OpKind::Add, &[one, yes]);
let stmt = b.expr_stmt(sum);
let body = b.block(&[stmt], None);
let main = b.func(Name::new(names.intern("main")), &[], body);
let root = b.module(None, &[main]);
let hir = b.finish(root)?;

let typed = check(&hir, &Profile::static_explicit()).unwrap();
assert_eq!(typed.diagnostics()[0].node, NodeRef::Expr(yes));
assert!(check(&hir, &Profile::dynamic()).unwrap().is_ok());
# Ok::<(), hir_lang::HirError>(())
```

### The static-explicit discipline

Declared types on parameters, returns, fields, constants, and globals; local
inference for `let` (including deferred initialisation) and for unsuffixed
literals, with profile defaults and range checks. Tuples, arrays, slices,
references, pointers, functions, nullables, maps, structural records, records,
sums, classes, and host and foreign nominal types; aliases with cycle
detection. Every OPS operation is typed by its operand types and its policy is
checked (`promote` is rejected on statically typed results); `Typed::op_class`
says how each one resolved. Calls match named, default, variadic, spread, and
by-reference parameters. Fields and methods resolve through `impl` blocks,
classes, base classes, references, and host members, borrowing and
dereferencing receivers automatically. Control flow, closures, `async`,
`await`, `spawn`, generators, `throw`/`try`/`catch` with type tests, casts,
intrinsics, and inline assembly operands are typed. Exhaustiveness: a variant
no unguarded arm can match is reported; matches that depend on nested patterns
are listed for match-lang.

### The dynamic discipline

Every value is `any`, annotations are not lowered, and the only diagnostics
are the ones that fail whatever the run-time values: argument lists that
cannot match a known function, constructors and constructor patterns of the
wrong length, unknown record fields.

### Partial paths

Paths that resolution resolved only partly (`Vec::new`, `Shape::Circle`,
`Self::zero`) are finished by type, and `Typed::path_def` reports what the
tail named.

### One root cause, one diagnostic

Expected types flow down to where a mistake is made, so a wrong literal is
reported at the literal; anything reported reads as the error type
afterwards, and the error type unifies with everything without binding shared
structure. Diagnostics carry stable codes (`T0001`...), the HIR node, and its
origin.

### Termination, complexity, budgets

Types are hash-consed; one union-find covers variables and compound terms,
merging classes before comparing children, so each pair of classes is compared
once (the `Pair(v, v)` doubling chain of type-lang's ISSUES M39 unifies in
linear time). The occurs check uses a visited set and skips variable-free
subterms in constant time; failed unifications roll back through a journal;
final types are resolved with one shared memo. Nothing recurses over the
input. A `Budget` bounds steps and type-store size; exhausting it is
`CheckError::BudgetExceeded`.

### Why type-lang is not wired

type-lang 1's unifier works on owned type trees: the doubling chain above is
exponential to build, resolve, and occurs-check through it (M39), and its
recursive `resolve`, `Clone`, and `Drop` overflow on deep types (M40). Both are
reachable through ordinary `let` inference, so the store lives here, internal,
and `dev/ROADMAP.md` recommends type-lang 2.0 adopt it.

## Not in this release

Generic items and arguments, traits and interfaces as types, associated
types, `impl` blocks on structural types, and interface conformance are
reported as `Unsupported` and scheduled for 0.5.0 with the `gradual`,
`static-inferred`, and `hm` disciplines (recorded in `dev/ROADMAP.md` under
the anti-deferral rule).

## Breaking changes

**None.** v0.1.0 had no public API.

## Verification

On Windows x86_64, Rust stable (1.95) and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Linux and the newest toolchain are run centrally.

Tests: 19 unit tests; 72 integration tests (rule by rule, adversarial and
scale, host declarations, dynamic); 6 property tests (typed generator: exact
types and method dispatch; single-mutation diagnostics at the mutation site;
error containment; determinism and dynamic acceptance; totality on arbitrary
repaired HIR under three profiles; any budget terminates) plus two coverage
tests that keep the generators from going vacuous; 111 doctests (including every `rust` block of `README.md` and
`docs/API.md`). The property tests were also run at 30,000–50,000 cases each in
release mode.

Benchmarks (`cargo bench --bench bench`, release, Windows x86_64, library
only). The machine was shared with concurrent builds (CPU at 100%), so these
are ranges across runs and upper bounds:

| Benchmark | Time |
|---|---:|
| `static-explicit`, 100k HIR nodes | 14.7–17.1 ms |
| `static-explicit`, 1M HIR nodes | 130–200 ms |
| `dynamic`, 100k HIR nodes | 3.6–5.7 ms |
| `dynamic`, 1M HIR nodes | 49–80 ms |
| Doubling chain, 100k levels (1.4M nodes) | 227–347 ms |
