# typeck-lang v0.3.0 — Static-Inferred: Generics, Traits, and a Monomorphization Plan

**The checker for Kraken and Iron.** v0.3.0 implements the `static-inferred`
discipline: bidirectional checking with local inference, generic functions and
types with bounds and where clauses, interfaces (traits) with methods, default
methods, and associated types, `impl` blocks (generic ones indexed like any
other), `dyn` and `impl Trait` types, closures whose signatures are inferred,
`?` through a profile hook, and a monomorphization plan with Iron's selective
policy. Exhaustiveness is now decided by match-lang, with the missing values
reported as patterns. The input is HIR v3 (hir-lang 0.4), so unions and
intersections are checked too. ISSUES P17 is addressed.

## What is typeck-lang?

The semantic-analysis (SEMA) crate of the `-lang` family that checks the HIR
every LexerSketch language lowers into, configured by a type-system profile
instead of written per language. It does not resolve names (resolve-lang).

## What's new in 0.3.0

### The static-inferred discipline

Everything `static-explicit` checks, plus closures typed from the expected
function type (or from use) and `let x = null` typed as a nullable inferred
from later uses. Generics and interfaces are available under both static
disciplines, since any HIR that uses them needs them.

```rust
use typeck_lang::{Discipline, NullLet, Polymorphism, Profile};

let p = Profile::static_inferred();
assert!(Discipline::StaticInferred.is_implemented());
assert_eq!(p.polymorphism, Polymorphism::Traits);
assert_eq!(p.null_let, NullLet::Nullable);
```

### Checking mode through generic calls

When a generic call has an expected type, a probe unifies the callee's
instantiated result with it and rolls back, and the arguments are checked
against what that says: in `let v: Opt<i64> = Some(true)` the mistake is
reported at `true`. Record literals of generic types take an expected instance
before their fields; pending interface goals are solved before a variable's
structure is needed.

### Generics

Generic functions, records, sums, classes, interfaces, impls, and aliases;
explicit (`f::<i32>`) and inferred arguments; defaults that may mention
earlier parameters; constant parameters and arguments (`Buf<4>`, `[T; N]`,
with `N` inferred from an array argument); bounds and where clauses checked
at instantiation, at construction, and in written annotations; `impl Trait`
parameters (anonymous generics) and results (opaque to callers, with the
hidden type reported by `Typed::opaque_type`). Instantiation is a memoized
substitution over the hash-consed type DAG, linear in the part that mentions
placeholders.

### Interfaces and traits

Methods, default methods, constants, associated types (`T::Item`,
`Self::Item`, `<T as I>::Item`, `I<Item = u8>`, `I<Item: Show>`), and
supertraits. Implementations are `impl` blocks, generic or blanket, and
classes' declared interfaces (inherited by subclasses), indexed by the head of
their self type; a lookup unifies only the candidates that could apply, inside
rolled-back snapshots. Member lookup goes through bounds, `dyn` types,
inherent members (and base classes), host members, and implementations (an
implementation's member overrides the default). `T::new()`,
`Iface::method(x)`, and `<T as Iface>::method` resolve by type. Overlapping
implementations, missing, extra, and mistyped members are reported. Receiver
auto-ref and auto-deref are a profile toggle (`method_autoref`).

### Exhaustiveness through match-lang

typeck implements match-lang's `Model` over its own types: sums, products,
nullable types (a sum of `null` and a value), unions (a sum of members matched
by type tests), integer and character domains, arrays and slices.

```text
T0027 non-exhaustive match: `Some(false)` not covered
T0040 unreachable match arm                      (a warning)
T0041 this alternative only matches values already matched   (a warning)
```

`Diagnostic::severity` distinguishes warnings; `Typed::is_ok` counts errors
only. `Typed::witnesses(match, names)` lists the missing values.

### The monomorphization plan

`Typed::mono_plan()` lists every instance of a generic function the program
reaches from its non-generic code: interface calls on placeholders are
resolved per instance (through generic impl chains), `dyn` coercions add
their vtables, and polymorphic recursion is reported and cut. The policy is a
profile toggle:

```rust
use typeck_lang::{MonoPolicy, Profile};

let iron = Profile::static_inferred().with_mono(MonoPolicy::Selective { max_nodes: 64 });
assert_eq!(iron.mono, MonoPolicy::Selective { max_nodes: 64 });
```

`Copy` copies every generic item, `Shared` shares every one through
dictionary passing (one body, plus the implementations its bounds need per
call site), `Selective` copies small items; `Checker::declare_mono_attribute`
lets an attribute (`@hot`) force a strategy. `Typed::instantiation(expr)`
gives the item, arguments, and dispatch (static, through a bound, dynamic) of
each use.

### `?` through a profile hook

A `?` lowered as a match template is ordinary code. A language that keeps it
as a named intrinsic sets `TryHook::Intrinsic { name, convert }`: the operand
must be a nullable or a two-variant carrier (option-like or result-like), the
expression has the success value's type, the function must return the same
kind of carrier, and an optional conversion interface (Rust's `From`) lets
failure types differ (`Coercion::ErrorConvert`).

### Unions and intersections

HIR v3's `int|string` and `A & B` are canonical types (`Types::union`,
`Types::intersection`): values coerce into unions containing them and out of
intersections, fields are found across members, type tests are checked
against members, and `match` exhaustiveness treats a union as a sum of its
members.

### P17 conventions

`let x = null` is a profile toggle (`Profile::null_let`). The generator
convention (the declared result is the yield type; `yield` and `yield from`
evaluate to unit), the value of assignments (the stored value, per HIR v3),
and `?` are recorded in `specs/HIR.md` §8.11.

### Termination and budgets

The union-find store keeps its guarantees (Huet merging, journaled rollback,
linear occurs check and zonking) and gains generic arguments, projections,
opaque types, unions, and trait objects. Nested interface resolution is capped
by the new `Budget::trait_depth`: `impl<T: Tr> Tr for T`, or an impl whose
where clause needs ever-larger types, is `CheckError::BudgetExceeded` with
`Limit::TraitDepth`, never a hang. Re-entrant lowering and normalization nest
at most 32 deep, so cyclic generic defaults and associated types stay within a
1 MiB stack. Unifying `{error}` with a structured type now binds that type's
variables to `{error}`, so an error node inside a generic expression stays one
root cause.

## Not in this release

The `gradual` and `hm` disciplines (0.5.0); associated types with parameters
of their own and multi-segment associated paths (`Unsupported`); object
safety of `dyn` interfaces; host-declared generic signatures. Orphan rules
depend on crate boundaries a unit does not see and belong to the app.
Recorded in `dev/ROADMAP.md`.

## Breaking changes

- hir-lang 0.4 (HIR v3) replaces 0.3; `not` requires `bool`, `bit_not` an
  integer; assignments have their target's type.
- `Type::Adt { item, args }`, `Type::Foreign { def, args }`,
  `Type::Extern { name, args }` replace the tuple variants; new `Type` views.
- `Typed::deferred_matches` is removed; `Diagnostic` gains `severity`;
  `Typed::is_ok` ignores warnings.
- `Feature` lists only what is still unsupported.
- `Budget` gains `trait_depth`; `Limit` gains `TraitDepth`.
- `Profile` gains fields (non-exhaustive: presets unaffected).

## Verification

On Windows x86_64, Rust stable (1.95), the newest installed toolchain (1.99),
and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo +1.99 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Linux is run centrally.

Tests: 20 unit tests; 126 integration tests, of which 54 are new: rule tests
for `static-inferred`, interfaces, generics, exhaustiveness, the plan and `?`
(38), a corpus of six Kraken-like programs, and ten adversarial tests (deep
generic arguments and calls, self-requiring and ever-growing impls, the
trait-depth budget, supertrait, alias, default, and associated-type cycles,
scale); 10 property tests, of which 4 are new over a typed generator of
generic programs (exact types with generic arguments, exact method targets,
exact plan instances; single-mutation blame; error containment; determinism),
and the arbitrary-HIR properties now cover generics, interfaces, impls, `dyn`,
`impl Trait`, unions, and the v3 forms under five profiles; 4 coverage tests
that keep the generators from going vacuous; 147 doctests (including every
`rust` block of `README.md` and `docs/API.md`). The properties were also run
at 60,000 cases (arbitrary HIR, generic programs) and 20,000 (0.2 programs) in
release mode.
